# Task C Acceptance — 可观测验收标准

> 状态：Draft v1。论述题的验收 = 逐要素核对 + 反向追问测试，不是跑命令。
> 验收人：本人（复面前必须能不看稿回答）。方法：对照下表逐条勾选；任一 ✗ 即不通过。

---

## 1. 逐问要素核对（映射 `C/spec.md` §4）

| 标准 | 问题 | 通过判据 |
| --- | --- | --- |
| C1-a | C1 | 有显式的最小调用序列，且每步附"证明什么 / 失败形态 / 处置" |
| C1-b | C1 | 明确区分 token 有效 / 租户已连接 / 租户数据权限 三层证明 |
| C2-a | C2 | 有显式决策树，覆盖题面五类原因（过期 / scopes / 租户头 / 权限 / 环境） |
| C2-b | C2 | 401、403、404 各自有可区分的可观测检查与修复动作 |
| C3-a | C3 | 分页 + 变更窗口 + 游标**页级提交后推进**三要素齐备 |
| C3-b | C3 | 去重键、部分失败、安全重放、晚到更新各有明确机制 |
| C4-a | C4 | 退避含抖动公式；并发上限、重试预算、死信处置齐备 |
| C4-b | C4 | 明确列出"不重试"的错误类别及理由 |
| C5-a | C5 | 有确定性引用作幂等键 + 重试前反查收养的路径 |
| C5-b | C5 | "成功但响应丢失"有对账任务与状态机收口 |
| C6-a | C6 | 日志/指标/告警/关联 ID 四项齐备且字段具体 |
| C6-b | C6 | "绝不记录"清单明确（token、授权码、敏感正文）；密钥存储与轮换策略具体 |

## 2. 证据与诚实性

| 标准 | 通过判据 |
| --- | --- |
| C-EVID | 每问结尾有 `Evidence:`，引用官方文档主题 + 核实日期；**逐条可打开**（验收时实际点击/请求全部链接） |
| C-ASSUM | 所有未文档证实的 API 行为处有 `Assumption:` 标注；无凭记忆断言的 URL / 头名 / 配额数字 |
| C-VER | 文首声明 SDK / API 版本假设 |

## 3. 篇幅与可读性

| 标准 | 通过判据 |
| --- | --- |
| C-LEN | 每问 150–300 词（`wc -w` 实测）；伪代码不计 |
| C-READ | 六问结构一致（要点列表优先、段落克制），无重复内容 |

## 4. 复面防御性验收（题面"解释不了代码即扣分"的等价物）

| 标准 | 通过判据 |
| --- | --- |
| C-DEF1 | 随机抽一问，**不看稿**口述 60 秒核心答案，覆盖该问 ≥3 个必答要素 |
| C-DEF2 | 对每问能回答"如果 Xero 文档变了这条怎么办"（指出该条是文档事实还是设计决策） |
