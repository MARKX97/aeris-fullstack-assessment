# Task B Spec — Fulfilment Split Optimiser（履约拆单优化器）

> 状态：Draft v2（实现期修订：§5 公式勘误、§8 oracle 强化、§9 新增 B5/B6）。变更需同步更新 `acceptance.md`。
> 依据：`BRIEF.md` §3。题面明说：**暴力子集枚举过不了最大用例**，且要求解释状态表示、平局策略与复杂度。

---

## 1. 问题陈述

给定 `W` 个仓库（各自有库存 `stock`、启用费 `fixed_cost`、单位成本 `unit_cost`）与订单量 `Q`，选出一套分配方案（每仓分配量 `a_i ∈ [0, stock_i]`，`Σ a_i = Q`，被使用的仓 `a_i ≥ 1`），使目标元组按**字典序**最优。不可行输出 `-1`。

## 2. Non-goals

- 不支持部分履约（必须恰好 Q，无缺额方案）。
- 不做多订单 / 多商品 / 库存维度约束（如重量、体积）。
- 不引入外部优化求解器（题面明文禁止）；纯标准库。
- 不做交互式输入；一次性 stdin → stdout。

## 3. 目标层级的形式化（消除题面歧义）

设使用集合 `S`，分配 `a`。`cost(S, a) = Σ_{i∈S} (fixed_i + a_i × unit_i)`。
可行解三元组 `(|S|, cost(S,a), L(S,a))`，其中：

```
L(S,a) = sorted [ (warehouse_id_i, a_i) for i in S ]      # 按 warehouse_id 升序
```

最优解 = 全体可行解中，元组 `(|S|, cost, L)` 字典序最小者。即依次比较：
1. 使用仓数更少者优先；
2. 仓数相同 → `cost` 更小者优先；
3. 前两者相同 → `L` 字典序更小者优先（`L` 视为 `(id, qty)` 元组的序列，逐元素比较；序列首个不同元素处决定胜负）。

**题面歧义假设 B1**：原文只说"按 warehouse_id 排序后字典序最小的 allocation list"，未定义比较粒度。本 spec 裁定为上述元组序列的逐元素比较（影响可见于 `acceptance.md` E-B3：`[(A,1),(B,2)] < [(A,2),(B,1)]`）。须写入 README。

## 4. 设计依据（引理）

**引理 1**：固定使用集合 `S` 与总量 `Q`，最小化 `Σ a_i·unit_i`（在 `1 ≤ a_i ≤ stock_i`、`Σ = Q` 下）可按 `unit_cost` 升序贪心装填。
证明思路：线性目标 + 独立容量区间，交换两个非满仓与非空仓的分配量即可消除逆序（exchange argument）。
用途：① 暴力 oracle 的构造器（见 §8）；② 实现后交叉验证。**不能**替代主算法——集合选择才是组合难点。

## 5. 候选方案与选型

| 方案 | 复杂度 | W=30, Q=2000 估算 | 结论 |
| --- | --- | --- | --- |
| ① 2^W 子集枚举 + 引理1 贪心 | O(2^W · W log W) | ~10^9 子集 | **淘汰**（题面明文） |
| ② 分层 DP：`dp[i][k][q]` = 前 i 仓、恰好用 k 仓、恰好凑 q 件的最小成本，转移需枚举本仓分配量 a | O(W·K·Q²) | ≈3.6×10^9 | 上界不可行，见下 |
| ③ 方案② + 滑动窗口最小值（单调双端队列）优化内层枚举 | O(W·K·Q) | ≈1.8×10^6 状态转移 | **选定** |

**方案③推导**（状态表示，题面要求解释的核心）：

```
dp[i][k][q] = min( dp[i-1][k][q],                          # 不用仓 i
                   fixed_i + f_i(q) )                     # 用仓 i（a ≥ 1）
其中 f_i(q) = min_{1 ≤ a ≤ min(stock_i, q)} ( a·unit_i + dp[i-1][k-1][q-a] )

代数变形：令 j = q-a，则 a·unit_i = (q-j)·unit_i，故
f_i(q) = q·unit_i + min_{ j ∈ [max(q-stock_i, 0), q-1] } ( dp[i-1][k-1][j] - j·unit_i )
```

内层 min 是对数组 `g[j] = dp[...] - j·unit_i` 的**定长滑动窗口最小值**——单调双端队列 O(1) 摊销，整体 O(W·K·Q)。

- 尺寸：`W ≤ 30`，`K ≤ min(W, Q) ≤ 30`，`Q ≤ 2000` → 状态 ≤ 1.86×10^6；Python 常数因子下秒级可完成。
- 数值：成本上界 ≈ 30×(10^6 + 2000×10^6) ≈ 6×10^10，Python int 无溢出。
- 内存：保留全部 i 层以支持重建 → ≤ 1.86×10^6 个 int，几十 MB 内。

## 6. 平局与重建（设计风险 R2）

最优 `(|S|, cost)` 确定后，需要重建出**字典序最小**的 `L`，而非任意最优分配：

- 重建规则：从最小的 `warehouse_id` 起，逐仓尝试"该仓是否在某个最优方案中被使用、且取最小可行分配量"，使前缀的 `(id, qty)` 序列字典序最小。
- 风险：`dp` 只存标量成本，不存分配向量；错误重建会通过 oracle 测试（§8）暴露。
- 缓解：重建采用**确定性**规则并在实现中单测覆盖 E-B3 类用例；禁止依赖迭代顺序的隐式行为。

## 7. 输入 / 输出契约

**输入**（stdin）：首行 `W Q`；随后 W 行 `warehouse_id stock fixed_cost unit_cost`。

**输出**（stdout）：
- 不可行（`Σ stock < Q` 或 DP 无解）→ 仅一行 `-1`。
- 可行 → 首行 `<仓数> <总成本>`；随后每行 `<warehouse_id> <分配量>`，按 id 升序。

校验：`qty`、`stock`、成本均按非负十进制整数解析；`warehouse_id` 非空 ASCII token；重复 id、越界数值 → 输出错误至 stderr 并以非零码退出（输入契约由题面约束保证，防御式处理即可）。

## 8. 测试计划（Feedback Sensors）

1. **官方示例**逐字节比对（E-B1）。
2. **Oracle 交叉验证（核心）**：小规模随机用例（W ≤ 8，Q ≤ 12，stock ≤ 6，成本 ≤ 8），**直接枚举全部可行分配**（递归 + 容量/成本剪枝），按 `(k, cost, L)` 三元组取最小作为 ground truth，与 DP 输出逐字节比对；≥100 组随机（固定 seed）。这是平局正确性的主要防线。相比"子集枚举 + 引理1 贪心"，全分配枚举不共享主算法的任何推理（连引理1 都不用），独立性最强（决策 B5）。
3. **定向用例**：不可行 / 零库存仓 / 成本打平 / 大数量（E-B2–E-B5）。
4. **性能**：题面上限尺寸的最坏构造（W=30、Q=2000、全仓 stock=2000），记录耗时（E-B6）。
5. **不变量**：任意输出满足 `Σ a = Q`、`0 ≤ a_i ≤ stock_i`、被使用仓 `a_i ≥ 1`、成本公式一致。
